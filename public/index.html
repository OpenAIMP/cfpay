Welcome to PaymentAgent

PaymentAgent is an AI agent that gets paid before it works. Send it a request, pay with a crypto wallet over the x402 protocol, and it processes the request with AI and emails you the answer. It can also send and receive email and pay other x402-enabled services on its own.

  • Pay & Process — submit a request and pay with MetaMask in ETH or USDC on Base or Ethereum Sepolia, or pay by card. The payment is verified before the agent starts.
  • Payments — a ledger of every payment received and sent, with amounts, status and transaction hashes.
  • Emails — inbound and outbound mail handled by the agent; replies are delivered to the address you provide.
  • Chat — talk to the agent directly and send email from the dashboard.

Trade approvals

Orders the model proposes wait here — nothing runs until you approve it. Approving executes exactly the call shown, through the approval workflow; rejecting (or waiting 24 hours) closes the proposal without executing anything.

Read-only by default

Public.com's server also exposes order placement, and their documentation warns that a trade placed through an MCP client is a real order using real money. This dashboard refuses order-placing tools unless the Worker secret PUBLIC_ALLOW_TRADING is set to true. With it set, an order-placing call still does not run directly: it becomes a proposal in the Trade approvals card above, and only your approval executes it. Reads — balances, quotes, option chains, holdings — work either way.

Autonomous QA

Run browser-based checks against any URL. Uses Cloudflare Browser tools.

Run Full Suite — runs every check below in order and returns one aggregate PASS/FAIL. The two email checks are included only when a recipient address is entered above.

Run QA Check — loads any URL in a headless browser and asserts the given text appears on the page.

Check This Dashboard — smoke test: dashboard loads, key text present, screenshot captured. Does not prove authentication on its own.

Verify Tab Data — clicks Emails, Payments and Webhooks and verifies each tab loads real data. Fails loudly on the login page.

UX Audit — deterministic design-rule checks on the rendered dashboard: contrast (WCAG AA), click-target size, heading hierarchy, button-style consistency across views, layout overflow/overlap, image alt text, and tab landing patterns. The rules are code, not a model — same page, same findings.

Audit URL — the same checks pointed at any web page. It defaults to the QA fixture page — the audit's self-test, with four planted violations it must catch — so clicking Audit URL as-is verifies the audit itself; paste any other URL to audit that page instead. Authenticated apps and multi-page targets go through the API spec (issue #94).

Test Attachment via UI — drives the real Send Email form, attaches a file and submits. Sends a real email; use a test recipient.

Check Payment Guards — verifies the 402 payment challenge is well-formed and malformed signatures are refused. Moves no money.

Check Edge Cases — wrong API key rejected, unauthenticated access rejected, unknown routes don't false-pass, errors are JSON not HTML.

Email QA Report — runs the tab checks on one shared browser session, then emails the report with a screenshot of the dashboard and of each tab attached (4 PNGs). Sends a real email.
